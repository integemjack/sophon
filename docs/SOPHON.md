# 智子（Sophon）—— 全自主 TUI 智能体

> 2026-10-14 用户新定义，**覆盖此前所有方案**（含 hermes 的 egui/eframe 桌面端方案、P1_DESIGN.md 的界面计划）。
> 用户原话：「全自主的解决用户提出的一切问题，遇到问题应该是想办法解决而不是告诉用户接下来怎么做直到能成功交付，
> 在交付结果的过程中也可以自我学习改进包括 hermes 本身，然后重新定义个程序的名字叫英语的智子缩写」。
> 名字：智子的英文译名 **Sophon**（三体），程序名 / 二进制名 `sophon`。
> 旧文档（ARCHITECTURE / ASSISTANT / REMOTE / TERMINAL / STYLE / POWERS / PORT_*）保留为**功能规格参考**：
> 它们描述 Friday 的功能与行为，智子继承其功能集，但界面层一律换成 TUI，部署层去掉远程/助手主机等桌面端概念。

---

## 0. 核心定义

1. **只有 TUI**：去掉桌面端 GUI。界面用 Rust 写（crossterm + ratatui），终端里跑，无窗口、无图形依赖。
2. **全自主**：默认自主执行——遇到问题自己想办法解决（重试、换方案、找替代路径、自愈），
   不把「接下来怎么做」推回给用户，直到成功交付。安全底线见 §4（不可逆破坏操作保留确认闸）。
3. **自我学习递归**：交付过程中持续学习——经验库记录「问题→尝试→结果→教训」，下次同类问题直接套用；
   发现自身缺陷时能改**程序本身**（分支改码 → 构建+测试验证 → 合并 → 重新编译），失败自动回滚并记教训。
4. **能解决用户提出的一切问题**：完整工具集（文件 / 命令 / 搜索 / 终端 / 子 Agent / MCP / 能力）+ 自主策略 + 经验库。

**资源约束**：免费服务器、资源有限 → **最小可用模型**：默认内置离线引擎（规则路由，零配置、零显存）；
可选本机 OpenAI 兼容服务（限 127.0.0.1/localhost）跑最小模型（1B 级 Q4）；不联网下载大模型。

## 1. 架构

```
┌────────────────────────────────────────────┐
│ sophon-tui（crossterm + ratatui）           │  界面层：三栏 TUI
│  会话列表 │ 对话区 │ Agent树/终端/状态板      │  键盘优先、实时刷新
├────────────────────────────────────────────┤
│ sophon-core（无界面核心 = 现有 hermes-core） │  整体复用，机械改名
│  models / store / engine / agent / tools /   │

│  + autonomy（新） + learning（新）            │
│  + selfimprove（新）                         │
└────────────────────────────────────────────┘
```

- **hermes-core 本来就无界面**（README：「无界面核心」），与 egui 零耦合 → 整体保留复用，只做包名/路径的机械改名。
- **hermes-app（egui/eframe 桌面端）按新定义移除**，由 sophon-tui 取代。
- 线程模型不变：回合线程跑 Agent 循环（工具执行、子 Agent），渲染线程只改界面状态；事件经通道推给 TUI 刷新。

## 2. 完整功能清单

### A. 会话管理
- 会话列表：按工作目录分组、搜索、置顶 / 改名 / 删除、新建
- 持久化（conversations.json；JSON 同构规则：UUID 大写、ISO8601 无毫秒、可选字段不写键）
- fork、分支切换

### B. 对话视图（TUI 中栏）
- Markdown 渲染：标题、粗斜体、删除线、行内代码、代码块、引用、有序/无序列表、**表格**、**任务列表**、链接、图片（本地路径）
- 流式输出（逐字刷新）
- 工具卡七态：运行中 / 成功 / 失败 / 待确认 / 已停止 / 已拒绝 / 排队（色标 + 展开看详情）
- 思考块（可折叠）
- 消息统计（token / 耗时）、复制、fork、朗读（TTS）
- 「已停止」「没有输出」等状态标注

### C. 输入栏（TUI 底栏）
- 多行输入、发送 / 停止（工作中发送 = 插话 interjection，作为「工作中补充」接进上下文）
- 附件（图片等路径）
- 模型 / 权限 / 思考 / 工作目录胶囊；工作中换模型标「下一轮生效」

### D. Agent 主循环
- 回合线程模型；停止状态机（is_stopping 只认第一次，连同子进程一起停）
- 审批（approve / deny）、恢复、重试
- 每轮验证检查点（verifyIfNeeded）
- 工作中换模型 / 换思考强度（本轮照旧，下一轮生效）
- 活性：看门狗（生成中 5 分钟无输出停）、deadline_seconds、原地打转检测（同调用第 3 次提醒、第 5 次拦下）、子 Agent 每 40 步提醒

### E. 全自主执行（新，§4 详述）
- 三级自主策略：`autonomous`（默认）/ `safe` / `yolo`
- 自动审批：只读、安全写入、非破坏性命令全自动放行
- 破坏性命令：先尝试可逆替代（回收站 / 备份 / 临时目录），无法替代才弹确认
- 硬拒绝列表：`rm -rf /`、格式化、关机等直接拒绝
- 错误自愈：工具失败 → 读报错 → 换方案重试（上限 N 轮）→ 仍失败才如实报告
- 交付自检：交付前跑构建 / 测试 / 验证，不绿不交付

### F. 工具集（22 个内置，全保留）
`run_shell`（审批/超时/取消/破坏性检测）、`read_file`、`write_file`、`edit_file`、`find_files`（glob）、
`search_files`（正则）、`search_keywords`、`read_terminal`、`run_in_terminal`、`update_task_state`、
`delegate_task`、`run_parallel_tasks`、`message_agent`、`stop_agent`、`wait_agents`、`rework_agent`、
`read_agent_log`、`list_tools`、`get_current_time`、`analyze_image`、`speak`，+ MCP 动态注册的工具

### G. 子 Agent 系统
- 团队状态（收件箱、队列、活动、运行中）
- 并行 / 后台 / 嵌套（层数不限；每轮派发上限默认 100；只派一个下级且任务相似度 ≥0.8 被拒）
- 互发消息（message_agent）、汇报（report_to_parent）、单独停止（stop_agent）、等消息（wait_agents）
- 用量统计（每个 Agent 的模型 / token）
- **Agent 树面板实时展示每个子智能体的运行 / 任务 / 日志 / 结果**（TUI 右栏，全自主也全程可见）

### H. 内置终端
- 标签页（每会话多个，标题取 Agent 命令 > 程序设的标题 > shell 名）
- ConPTY + VT 模拟（16 色 / 真彩 / 光标 / 滚动缓冲 5000 行 / 鼠标模式）
- Agent 可读写（read_terminal / run_in_terminal）；TUI 内嵌终端视图（选择 / 复制）

### I. 助手运行时
- 时间线（按天分隔、分页）、状态板（各会话实时状态）、记忆（条目 / 关键词检索）、话题摘要（按项目滚动）

### J. MCP 客户端
- 连接本机 stdio MCP 服务，取其工具（不联网）

### K. 大脑（引擎）
- **离线引擎（默认）**：规则路由，零配置可用（找文件 / 读文件 / 跑命令 / 派子 Agent / 问答）
- **本机 OpenAI 兼容引擎**：Ollama / llama.cpp / LM Studio，地址限 127.0.0.1/localhost（构造时校验，拒绝云端）
- 最小模型策略：优先最小可用模型；资源不足回退离线引擎

### L. 密钥库
- API Key 只以名字流转、明文加密落盘（secrets.json）

### M. 自我学习（新，§5 详述）
- 经验库（lessons.jsonl）：问题 → 尝试 → 结果 → 教训
- 每次交付后自动总结写入；新任务先检索经验库
- 错误模式库：同类错误第 2 次直接套用已知修法

### N. 自我改进递归（新，§6 详述）
- 自修改管道：发现自身缺陷 → git 分支改自身代码 → cargo build + cargo test → 全绿 → 合并 → 重新编译 → 交付
- 失败自动回滚 + 记教训；用户随时可审阅（git log / diff）与回滚

## 4. 全自主执行策略（autonomy.rs）

三级（设置里切，默认 `autonomous`）：

| 级别 | 只读/安全写入 | 非破坏命令 | 破坏性命令 | 硬拒绝列表 |
|---|---|---|---|---|
| autonomous（默认） | 自动 | 自动 | 先试可逆替代，不行才确认 | 拒绝 |
| safe | 自动 | 确认 | 确认 | 拒绝 |
| yolo | 自动 | 自动 | 自动 | 拒绝 |

- **破坏性检测**：`isDestructive` 规则（删除 / 格式化 / 覆盖 / rm -rf / git reset --hard …）。
- **可逆替代**：删除 → 移到回收站/备份目录；覆盖 → 先备份；`rm -rf dir` → 先打包再删。替代失败才弹确认。
- **硬拒绝**：`rm -rf /`、`mkfs`、关机 / 重启、结束自身进程等——直接拒绝并说明。
- **错误自愈**：工具返回 Err → 把报错喂回大脑并自动重试（换参数 / 换工具 / 换路径，最多 3 轮）→ 仍失败如实报告。
- **交付自检**：任务声明完成前，若工作目录有构建 / 测试脚本，自动跑一遍；不绿就继续修，直到绿或如实报告卡点。

## 5. 自我学习（learning.rs）

- 经验库 `lessons.jsonl`（数据目录下）：`{ts, problem, attempts[], result, lesson, tags[]}`。
- 写入时机：每次交付后（成功与失败都写）；工具连续失败后；用户纠正后。
- 检索：新任务开始前按关键词 / 向量（无模型时用关键词）检索 top-k 相关教训，拼进上下文。
- 错误模式库：同一报错出现第 2 次 → 直接套用上次的修法，不再试错。

## 6. 自我改进递归（selfimprove.rs）

- 触发：用户报告自身缺陷 / 交付中发现自身 bug / 用户显式「改进自己」。
- 管道：`git checkout -b self-improve/<ts>` → 改自身代码（用同一套工具）→ `cargo build` + `cargo test` →
  全绿 → `git merge` → 重新编译二进制 → 交付说明（改了什么、为什么、测试结果）。
- 任一步失败 → `git checkout` 回滚 + 把失败写进经验库。
- 约束：只在工作目录的 git 仓库内操作；测试必须全绿才合并；保留回滚点；用户可随时 `git revert`。
